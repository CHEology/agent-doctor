## 1. 目的、状态与边界

本文把阶段 01 已确认的产品行为和阶段 02 的诊断语义转化为 Codex-first 本地 CLI MVP
可实现、可测试的架构，定义领域契约、组件边界、数据与控制流、失败语义、修复安全、
结果表示和追踪关系，不包含产品实现代码。

PRD 与分类法仍然具有最高约束力，尤其包括：

- 分析默认只读；
- 确定性诊断在本地离线完成；
- 用户显式要求完整诊断时默认执行语义分析，同时允许关闭或缩小；模型披露与执行仍须
  绑定精确 manifest；
- 静态证据不能证明运行时选择或因果关系；
- 准确性与可解释性优先于覆盖率；
- `pass`、`finding`、`candidate`、`insufficient_evidence`、`not_run`、
  `error` 是检查状态，不是冲突类别；
- 实质标签与 `runtime_validation_needed` 保持为独立输出轴；
- 每项受支持写入都必须精确预览、得到边界授权、完成验证、留下记录并可安全回退。

阶段 04 才会物化测试数据、场景、测量协议与质量门禁；阶段 05 才会选择实现技术并编写
代码。本文不代表已经完成上述任一后续阶段。

## 2. 架构目标、约束与信任边界

### 2.1 目标

1. 生成一份有证据支持的底层诊断结果，终端、Markdown、JSON 和 CI 只能投影该结果，
   不能各自重新裁决；
2. 每个确定性结论都能由观察事实和带版本的平台/规则依据复现；
3. 保留不确定性和部分覆盖，绝不把二者转成通过；
4. 最小化文件读取和模型披露范围，任何范围扩大都必须事先可见；
5. 分离诊断、修复规划、授权、应用、验证与回退，前一项能力不自动包含后一项权限；
6. 在应用和回退前发现并发变更，拒绝不安全覆盖；
7. 对 Codex 平台相关行为记录来源、版本并允许替换；
8. 为评审、基线和后续测量提供稳定标识和完整版本元数据。

### 2.2 约束

- MVP 是本地、Codex-first CLI，不是托管服务或通用 Agent 平台；
- 输入限于 PRD 支持的来源；任意项目文档、脚本和外部文件不会隐式进入范围；
- 确定性模式不得依赖网络、凭证或模型；
- 语义分析只能增加覆盖，不能把推断升级为确定性证明；
- 运行时轨迹收集和因果验证被推迟；
- 修复操作使用明确允许列表。尚未实现或不可回退的改动可以作为手动建议，但 Agent
  Doctor 不得自动应用；
- 产品验收阈值是目标，本文不会把它们转成已经达到的保证。

### 2.3 信任边界

| 边界 | 可以信任的内容 | 不可信内容/必须防护的风险 |
| --- | --- | --- |
| 本地文件系统 | 某一观察时刻返回的字节与元数据 | 多次读取间稳定性、符号链接/路径替换、可读性、内容安全与保密性 |
| 用户或 CI 调用者 | 选择初始工作区、模式与策略 | 分析同意不等于写权限；非交互调用不能伪造确认 |
| Codex 平台行为资料 | 与兼容 profile 对应且明确引用的规则 | 未记录行为、过期版本、未来行为或运行时遵守情况 |
| 模型提供商 | 返回可选语义假设 | 确定性真相、授权、稳定可用性或超出已披露条款的秘密处理 |
| 被分析配置内容 | 声明范围内的待检查数据 | 其中针对 Agent Doctor 的指令、授权声明、脚本安全或元数据真实性 |
| 输出目的地 | 接收最小化结果 | 除非用户选择了合适目的地，否则不保证保密；渲染器必须防止泄露排除内容 |
| 变更记录存储 | 保存可归因恢复资料 | 架构本身不保证无限保留或防护；访问和保留策略必须披露 |

被诊断文件始终是不可信数据。Agent Doctor 不执行脚本、不服从被分析内容中的指令，也
不把配置文本视为授权。模型响应同样是不可信输入，必须经过验证和本地裁决。

### 2.4 明确推迟的决定

本文不决定：实现语言和框架、解析库、数据库或文件物理格式、摘要算法、准确 CLI 语法、
数字退出码、模型厂商/型号、凭证存储、界面措辞、具体修复操作清单、跨文件原子机制、
操作系统文件原语、可选缓存加密，以及阶段 04 的策略阈值。后续选择必须满足本文契约。

## 3. 架构形态与依赖规则

系统由一条分析流水线和一条独立的、能力受控的变更路径组成：

```text
范围方案 -> 盘点 -> 解析/规范化 -> 确定性解析/规则 -> 默认语义问题规划
                                                 -> 已同意的提供商分析
                         -> 裁决 -> 分组 -> 结果集 -> 渲染/CI

所选问题 -> 修复方案 -> 精确预览 -> 授权校验 -> 前置检查/保存旧状态
         -> 应用 -> 验证 -> 变更记录 -> 回退前置检查 -> 回退 -> 验证/记录
```

下游组件可以增加带类型的事实或决定，但不能删除或改写上游证据类型。渲染器不能执行
检查；语义分析不能写文件；修复组件只能使用已冻结的问题和来源版本，不能借修复之名
静默扩大扫描范围。

## 4. 领域模型与不变量

### 4.1 核心实体

| 实体 | 必须表达的含义 |
| --- | --- |
| `AnalysisRun` | 一次调用：运行 ID、开始/结束时间、产品与契约版本、模式、冻结范围、覆盖情况和运行结果。 |
| `AnalysisScope` | 规范工作区根、所选路径/任务区域、来源类型、配置模式、允许的外部根、排除项、本地检查边界、语义披露边界与修改边界；各边界彼此独立。 |
| `PlatformProfile` | 带版本、可归因的 Codex 发现、优先级、引用、schema 和上下文预算规则，包含资料来源、兼容范围和状态。 |
| `Source` | 一次来源出现：稳定逻辑身份、类型、规范位置、声明/实际范围、发现状态、可读性、版本指纹、敏感标记与来源链。 |
| `SourceSnapshot` | 在明确观察时刻捕获的字节或获批摘录及元数据；内容可被保留不展示，但元数据仍可作为观察证据。 |
| `Claim` | 最小且保留原始措辞/限定条件的规范化义务、禁止、许可、触发、范围、输出约束、引用或配置断言。 |
| `ApplicabilityRegion` | 由路径、请求/任务见证、模式、条件、包含/排除构成的表达式；交集状态为已证明、推断、为空或未知。 |
| `Dimension` | 交互主题，如必做动作、禁止动作、提问策略、输出形式、触发、引用有效性、配置、优先级或上下文使用。 |
| `EvidenceRecord` | 不可变的观察、推导、推断或运行证据，含生产者、时间、来源、规则/提供商归因、敏感处理与血缘。 |
| `CheckDefinition` | 稳定检查/规则 ID 与版本、可评审问题模板、支持的模式/来源类型、必需前置条件、决定契约和可能的覆盖/失败结果。 |
| `CheckExecution` | 一个明确问题与检查族的生命周期、最终检查状态、原因、覆盖、输入版本和证据引用。 |
| `InteractionCase` | 最小裁决单元：冻结问题、来源/主张、共享区域、维度、证据、三个输出轴、影响、置信度、反例和下一步。 |
| `SubstantiveAssessment` | 作用于明确主张 ID、区域 ID 和维度 ID 的实质标签；仅在多标签规则允许时共存。 |
| `ValidationQualifier` | 限定一个具体假设；MVP 当前只有 `runtime_validation_needed`。 |
| `FindingGroup` | 将实质相同案例合成一个用户问题，同时保留全部案例和证据位置。 |
| `NextAction` | 有边界的手动步骤、证据请求、运行时验证命题、修复方案请求或无需行动说明；自身不携带权限。 |
| `ResultSet` | 一次运行的不可变规范结果图，包含盘点、覆盖、检查、案例、分组、诊断、版本和可复现元数据。 |
| `RepairProposal` | 由所选结果与来源版本生成的精确不可变方案，含目标、操作/差异、理由、影响、风险、验证、回退、前置条件与摘要。 |
| `AuthorizationGrant` | 独立签发的能力：授权 ID、主体/会话、规范目标限制、操作类别、有效期/会话、撤销状态及可选方案摘要绑定。 |
| `ChangeRecord` | 一次应用/回退的可归因记录：方案和授权、操作者/会话、各目标前后指纹、受保护旧状态、验证和明确总状态/逐目标状态。 |

### 4.2 证据与来源链

证据类型封闭且不可互换：

- `observed`：直接读取的文本、路径、元数据、存在性、可读性、配置、同意、模式或文件
  状态；
- `derived`：观察证据与带版本的明确规则产生的可复现结果；必须引用父证据和推导规则；
- `inferred`：语义解释；模型输出在没有独立确定性推导时全部属于此类；
- `runtime`：在记录条件下实际执行产生的证据；领域模型保留该类型，但 MVP 没有生产者。

证据记录只追加不改写。渲染器可以脱敏展示，但不能改变类型。多个模型一致仍然只是
推断。后续确定性/运行证据可以佐证推断，但不能追溯修改其来源属性。

### 4.3 状态、标签、限定符、严重程度与置信度不变量

MVP 的实质标签注册表包含 `semantic_conflict`、`scope_overlap`、
`behavioral_redundancy`、`complementarity`、`precedence_override`、
`invalid_reference`、`stale_reference`、`context_budget_risk` 和
`configuration_risk`。`no_material_relation` 是受下述限制的黄金/对照标签，不是问题
finding。每个注册项都绑定分类法版本，检测器或模型提供商无权增加、删除或重新定义。

1. 每个定义的检查只有一个最终状态：`pass`、`finding`、`candidate`、
   `insufficient_evidence`、`not_run` 或 `error`；
2. 状态不能存入实质标签字段；
3. `not_run` 必须命名跳过的检查和原因，不赋实质严重程度/置信度；
4. `error` 必须命名已尝试操作和失败，不虚构配置缺陷或严重程度；
5. `insufficient_evidence` 必须说明缺失决定性证据和最小解决步骤；其置信度只表示对
   “应拒绝判断”的把握；
6. `finding` 必须达到对应规则的决定性证据门槛；
7. 低置信实质问题通常保持 `candidate`；
8. `runtime_validation_needed` 只限定准确、可证伪命题，通常依附候选，不能升级状态；
9. 严重程度表示影响，独立于置信度；潜在严重程度与已成立问题的严重程度分开；
10. 对相同主张、区域和维度，冲突、重复与互补不能共存；只有不同维度/子区域时才能
    同组出现；
11. 已由覆盖解决的矛盾不能继续作为实际语义冲突；
12. `no_material_relation` 用于黄金对照或解释性 pass，不作为问题 finding 输出。

### 4.4 范围与来源不变量

1. 扫描前展示的范围必须冻结并可计算摘要；修改范围后必须生成新版本并重新展示；
2. 发现、本地检查、语义披露、修改和回退目标分别表示；
3. 进入一个范围不代表自动进入另一个范围；
4. 每个被发现、忽略、遮蔽、截断、缺失、不可读或主动排除的受支持来源都有盘点记录；
5. 路径规范化不能为边界外路径创造权限；
6. 引用按声明文件和明确解析规则解析，不能相对进程工作目录；
7. 只靠规范路径元数据即可判定越界时，不得读取外部目标；
8. 适用与实际生效分开：已发现来源仍可能不合格、不适用、被遮蔽或实际生效；
9. 未知平台行为不能用直觉补成优先级/预算规则，相关问题必须拒绝判断或成为条件候选。

### 4.5 身份、分组和版本不变量

- 运行 ID 与证据出现 ID 每次运行唯一；规则、检查、来源逻辑身份、案例指纹和分组指纹
  在规范输入与契约版本不变时保持稳定；
- 案例指纹来自规则/问题、逻辑来源与主张、区域、维度及相关规范化/分类法版本，不包含
  时间戳、可用工作区相对身份替代的用户绝对路径、秘密或渲染文案；
- 决定性主张或范围改变会产生新指纹，不能沿用旧基线身份掩盖变化；
- 分组有明确版本和理由，不得丢弃成员、证据、维度或位置；
- 产品、结果 schema、分类法、规则集、规范化、平台 profile 与语义契约分别版本化。

## 5. 组件边界与职责

| 组件 | 职责 | 禁止事项 |
| --- | --- | --- |
| CLI/会话协调器 | 解析调用意图，建立运行/会话身份，编排能力，显示范围/同意/预览，选择输出。 | 推断写权限、自行裁决或隐藏覆盖缺口。 |
| 范围展示与策略守卫 | 生成并展示发现/检查/披露/修改范围，冻结范围并执行边界检查。 | 因发现引用而未经新披露扩大范围。 |
| 平台 profile 注册表 | 提供带版本、带来源的 schema、发现、优先级、引用和预算规则。 | 猜测未记录行为或静默切换平台版本。 |
| 发现与盘点 | 在冻结范围内枚举受支持候选、来源链、状态和元数据。 | 语义裁决、跟随禁止引用或省略不可访问来源。 |
| 安全读取/内容代理 | 管理元数据/内容读取、摘录、脱敏、敏感分类和模型合格内容。 | 执行内容、泄露未批脚本/秘密、把检查许可等同模型同意。 |
| 解析与规范化 | 产生快照、结构声明、主张、限定词和精确位置诊断。 | 解决语义冲突、丢弃原文或规范化掉语气/排除项。 |
| 引用与配置解析器 | 按规则解析声明、schema、存在/可读/类型、越界与兼容事实。 | 为确认越界而读取外部文件，或只凭年龄判陈旧。 |
| 优先级与适用性解析器 | 建来源链、适用区域、实际/潜在主张和共享区域事实。 | 虚构胜者或声称运行时遵守。 |
| 确定性规则引擎 | 对类型化事实执行重复、有效性、元数据、优先级与预算检查。 | 调模型、使用无版本限制、把失败当 pass。 |
| 语义协调器 | 选择最小内容，执行披露/提供商门控，调用适配器，校验响应和引用，记录推断。 | 默认发送秘密/脚本、授予权限或直接把模型标签发布成 finding。 |
| 提供商适配器 | 映射中立请求/响应，并暴露提供商/模型/策略元数据。 | 访问任意文件或决定 Agent Doctor 状态/严重程度。 |
| 裁决器 | 执行分类法顺序、反例、多标签、置信度/严重程度和拒绝判断规则。 | 覆盖上游错误或把推断改成观察/推导证明。 |
| 去重与分组器 | 计算稳定案例/分组身份，将同一用户问题合并。 | 仅因文件相同而合并不同问题、区域或维度。 |
| 结果装配器 | 校验不变量，封存包含覆盖与可复现元数据的规范结果集。 | 在渲染时重新分析。 |
| 终端/Markdown/JSON 渲染器 | 从同一结果图输出不同详细度且秘密安全的视图；在不改变结果的前提下排序复核项。终端展示最严重项、代表性较轻项、引用原句/模型理由/反例来源及明确省略计数，Markdown/JSON 保留完整细节。 | 改变状态、标签、严重程度或覆盖；把尚未提问或回答的语义问题写成风险。 |
| CI 策略评估器 | 按独立配置阈值输出 `satisfied`、`policy_failed` 或 `execution_failed`。 | 删除低于阈值的长期结果，或混淆策略失败与工具失败。 |
| 修复规划器 | 把所选问题转换为允许列表内、可回退的精确方案与验证计划。 | 写文件、扩大目标或把不支持写入标成可自动应用。 |
| 授权服务 | 签发/导入、校验、撤销、过期边界授权；精确确认绑定方案摘要。 | 把分析/模型同意当授权，或放宽目标/操作限制。 |
| 应用协调器 | 复核预览、授权、路径、版本、前置条件，捕获旧状态，执行获批操作并记录。 | 应用时重新规划、权限失效后继续或覆盖并发变更。 |
| 变更后验证器 | 在原范围内验证精确后状态和方案特定条件。 | 因写调用成功就直接宣称验证成功。 |
| 变更账本/回退协调器 | 保存可归因记录和受保护旧状态，核对当前后状态，安全恢复并验证。 | 在不匹配时回退，或没有旧状态却宣称可恢复。 |

## 6. 技术中立的组件契约

每个契约返回值和类型化诊断；普通局部失败不能只靠进程退出表达。输入必须显式包含范围
和版本，不能依赖环境工作目录。

| 契约 | 输入 -> 输出 | 失败与幂等语义 |
| --- | --- | --- |
| `PlanScope` | 用户选择 + 平台 + 模式 -> 已展示 `AnalysisScope` | 根路径无效/含糊则不开始；相同输入产生相同规范范围摘要（不含观察时间）。 |
| `Inventory` | 冻结范围 + 平台 profile -> 来源记录 + 覆盖事件 | 保留逐来源访问失败；无法检查根时相关检查为 error；只读，同一文件快照下可重复。 |
| `ReadSource` | 来源 ID + 允许目的 -> 快照/摘录或类型化拒绝/失败 | 范围拒绝不能靠扩大访问重试；读取无副作用并携带版本指纹。 |
| `ParseAndNormalize` | 快照 + schema/规范化版本 -> 主张 + 诊断 | 畸形内容可产生部分主张，但必须带解析错误和完整性标志；相同字节/版本语义等价。 |
| `ResolveReference` | 声明 + 来源位置 + 范围 + resolver profile -> 目标/状态/证据 | 永不读取越界目标；不支持语法不能猜路径。 |
| `ResolveApplicability` | 主张 + 来源链 + 范围 + 优先级 profile -> 区域/生效性/血缘 | 缺关键规则则生效性未知并依赖拒绝判断；相同输入/profile 可复现。 |
| `RunDeterministicCheck` | 检查定义 + 类型事实 -> 检查执行 + 案例 | 开始后内部失败为 error；缺范围内关键事实为证据不足；关闭/超范围为 not_run；无网络。 |
| `BuildSemanticDisclosure` | 候选问题 + 合格摘录 + 策略 -> 精确披露清单 | 被排除的决定性内容仍须排除并导致拒绝判断；摘要绑定提供商和内容句柄。 |
| `RunSemanticCheck` | 已同意清单 + 提供商配置 -> 响应封装 + 推断证据 | 开始前不可用为 not_run；开始后传输/schema 失败为 error；完成后的含糊由裁决器作候选/拒绝；重试不得重复 finding。 |
| `Adjudicate` | 问题 + 类型证据 + 分类法版本 -> 交互案例 | 不变量违规形成架构诊断，不能强行给标签；相同证据/版本产生语义等价结果。 |
| `GroupCases` | 案例 + 分组版本 -> 分组 + 成员映射 | 稳定、无损，重复运行不重复成员。 |
| `Render` | 封存结果 + 渲染策略 -> 终端/Markdown/JSON | 展示失败不修改结果；必须标脱敏且不能隐藏覆盖缺口。 |
| `EvaluateCI` | 封存结果 + 明确策略 -> CI 结果 + 策略决定 | 纯函数且幂等；策略失败与执行失败分开；数字退出码后续选择并记录。 |
| `ProposeRepair` | 稳定 ID + 当前版本 + 操作允许列表 -> 方案或手动行动 | 纯规划；相同规范输入产生相同方案摘要；零写入。 |
| `ValidateAuthorization` | 方案 + 授权 + 会话/时间/撤销状态 -> 决定 | 应用前和每个操作前复核；拒绝时零写入；确认仅限单方案且单次使用。 |
| `ApplyProposal` | 精确方案 + 有效决定 -> 变更记录 | 对“方案/尝试”键最多执行一次；重放返回旧结果；首个冲突/失败即停，逐目标标明状态。 |
| `VerifyChange` | 方案 + 观察后状态 -> 验证结果 | 只读、可重复、目标有边界；区分精确后状态、诊断条件和验证错误。 |
| `RollbackChange` | 变更记录 + 当前状态 + 回退授权 -> 回退记录 | 写前预检全部目标；任一后状态不匹配则零写入拒绝；重放返回已有结果。 |

## 7. 端到端数据与控制流

### 7.1 离线确定性诊断

1. 协调器构建并展示分析范围：根、来源类型、排除项、检查边界、语义模式/选择策略和
   只读权限；
2. 范围守卫冻结范围和平台 profile；
3. 盘点记录所有受支持候选及发现、忽略、遮蔽、截断、缺失、不可读、排除状态；
4. 内容代理只读获批的本地元数据/内容并产生版本化观察；该路径不存在网络调用；
5. 解析器保留原文和限定词，同时生成规范声明与主张；
6. 引用/配置和优先级/适用性先于语义比较；所有推导引用 profile 和父证据；
7. 确定性规则尽可能独立执行，一个来源失败不抹去无关结果；
8. 裁决器执行有序程序、共享区域证明、逐维度比较、反例和拒绝判断；
9. 无损分组并封存一个含覆盖缺口和版本的结果集；
10. 所有渲染器与 CI 使用该结果；普通确定性扫描没有 provider panel 时，把已开启的
    语义工作标为“等待执行”；关闭或不可用的语义检查族明确为 `not_run`，绝不能写成 pass。

### 7.2 默认语义规划与 manifest 绑定的模型诊断

1. 先完成确定性发现与解析；
2. 语义协调器默认规划范围内、语义分析有价值但尚未解决的问题；精确纳入/排除选择器
   可以缩小有边界的自动范围；
3. 内容代理排除凭证、检测到的秘密、脚本正文、未获批正文、无关引用文件和非决定性
   上下文，生成最小摘录与内容句柄；
4. 独立调用前展示披露清单：提供商、可知的模型/配置身份、来源位置、内容类别、排除项、
   用途和已知提供商保留/缓存事实；用户显式发起的一键完整诊断只授权紧接着生成的
   manifest，并在 provider 启动前把同样字段写入本地审计产物。两条路径都绑定精确摘要，
   且与写权限分开；
5. 两个盲审分析 Agent 在隔离的临时上下文中并行运行，以正序/逆序查看同一冻结问题和
   证据，彼此不可见，并为每个问题返回一份带引用的答案；
6. 两份答案都通过校验后，第三个全新上下文的仲裁 Agent 才能读取二者和已披露句柄，
   记录共识、已裁决分歧、挑战或证据不足，但不能决定产品状态、严重程度、置信度、
   证据来源或修复权限；
7. 中立请求只包含冻结问题、相关主张/限定词、区域/维度、获批摘录、必要分类法含义和
   拒绝判断要求，不包含任意仓库上下文或原始凭证；
8. 适配器校验结构、角色/问题关联及对已提供句柄的引用；响应以推断证据记录，并保存提供商、模型、
   适配器、提示契约、请求和输入摘要来源链；
9. 状态、标签、限定符、严重程度和置信度由本地裁决器决定；只有经仲裁确认的双分析者
   共识才可能成为决定性结论，仲裁后的分歧最多形成 candidate；
10. 封存结果同时保留确定性结果和准确的语义覆盖/结果。

### 7.3 降级、未运行、证据不足与错误

| 条件 | 必须行为 |
| --- | --- |
| 语义模式关闭，或检查开始前提供商不可用 | 确定性运行完成；相关语义检查逐项 `not_run` 并说明原因。 |
| 提供商请求开始后超时、失败或结构不可用 | 相关检查 `error`；已有确定性/语义结果保留。 |
| 检查完成但缺决定性获批内容或平台规则 | `insufficient_evidence`，说明缺失事实、原因与有限下一步。 |
| 静态证据支持可证伪运行命题 | `candidate` + 对应标签 + `runtime_validation_needed`；不声称运行结果。 |
| 有效性检查中来源变为不可读 | 该检查 `error`；之前独立 finding 保留；依赖它的下游问题可另行拒绝判断。 |
| 结果装配不变量失败 | 运行结果为执行失败，保留可审阅局部诊断，不能输出伪装完整的规范结果。 |
| 单个渲染器失败 | 规范结果和其他输出仍有效，单独报告输出错误。 |
| 有效结果超过 CI 阈值 | `policy_failed` 而非 `execution_failed`；长期报告仍含全部 finding。 |

运行总体结果独立于逐项检查状态。`complete` 表示已封存有效结果，每个已启用且范围内
的检查都到达非 error 终态，并且所有 `not_run` 都已在冻结方案中声明为关闭或超出范围；
`complete_with_gaps` 表示已封存有效结果，但预期能力不可用、检查出错或前置条件仍不完整；
`execution_failed` 表示无法封存可信规范结果。
三者都不改变逐项检查状态。CI 还必须声明哪些检查族/模式属于执行必要项：必要项未满足
时为 CI `execution_failed`；覆盖充分的有效结果超过 finding 阈值时为 `policy_failed`；
可选缺口保持可见，但不会自动变成策略通过或失败。

### 7.4 修复方案与边界授权

1. 用户选择稳定 finding/case ID，选择本身不授权写入；
2. 规划器确认操作属于受支持、可回退允许列表，且目标在修改范围内；
3. 生成不可变方案：规范目标、精确前后状态/等价操作表、来源版本前置条件、理由、影响、
   风险、验证、旧状态需求、回退可用性和方案摘要；
4. 每次写入前展示精确方案，已有预授权也不能跳过；
5. 只有下列之一满足才允许写：
   - 有效授权的规范目标、操作类别、会话/主体、有效期和撤销状态覆盖精确方案；
   - 用户明确确认此方案摘要、会话、目标和操作；
6. 扫描同意、检查许可、模型披露都不能替代授权；方案改变会产生新摘要并重新授权；
7. 应用开始和每个操作前都检查撤销/过期；权限失效后停止后续写入并记录。

### 7.5 应用与验证

1. 再次解析规范目标，确保没有新路径/链接替换，仍处于修改范围并匹配方案身份；
2. 对全部目标预检预期版本、类型、符号链接身份、操作所需权限和特定条件；任一不匹配
   则零写入；
3. 首次写入前捕获精确旧状态与恢复所需元数据；无法持久、安全保存时该操作不受支持；
4. 再次校验方案摘要、授权、撤销和过期；
5. 每项操作前再次检查目标身份、路径和版本前置条件，再按获批顺序执行且不重新规划；
   必须使用能够关闭“检查后、写入前”竞态的目标内比较替换或等价原语；当前平台无法为
   某操作提供足够保护时，该写入类型在此平台不受支持；不承诺跨目标原子性；
6. 每项操作后记录实际后状态；失败/权限丢失即停止，不执行未获批补偿。总状态明确区分
   `applied`、`partially_applied`、`rejected`、`conflicted`、`failed`，并含逐目标状态；
7. 分开验证精确后状态和方案特定条件；写成功不等于验证成功，必要时使用
   `applied_unverified` 或 `verification_failed`；
8. 封存不含原始凭证/无关秘密的归因记录，并显示有限回退操作。

### 7.6 安全回退与并发变更保护

1. 回退只引用一份已封存变更记录及其中成功写入的目标，并需要反向操作权限；
2. 写入前核对所有目标当前身份/内容/元数据与记录后状态；除非反向操作明确支持该状态，
   缺失或改变都视为冲突；
3. 任一目标不同，整次回退在零写入情况下拒绝，报告冲突并保留当前状态与恢复资料；不
   覆盖也不自动合并无关工作；
4. 全部匹配后，每项反向操作前再次核对身份与后状态，再用目标内竞态安全原语恢复旧
   状态；若此时出现新不匹配，则不覆盖该目标并立即停止；此前已有目标完成恢复时，记录
   必须明确标为 `rollback_partially_applied`。验证旧指纹/元数据，并记录
   `rolled_back`、`rollback_conflicted`、`rollback_partially_applied`、
   `rollback_failed` 或 `rollback_verification_failed` 及逐目标状态；
5. 重放已完成回退只返回既有结果，不再次变更。

## 8. 发现、范围与平台规则边界

### 8.1 明确的范围集合

架构不使用一个含义过载的“范围”，而维护以下集合：

- `discovery_candidates`：带版本适配器可枚举的位置；
- `inventoried_sources`：全部观察候选及状态；
- `inspection_eligible`：本地确定性分析可读取的来源/内容；
- `applicable_sources`：声明/路径条件与所选任务区域相交的来源；
- `effective_claims`：应用确定性优先级后保留的主张；
- `semantic_eligible`：明确披露后可发送模型的精确内容；
- `modifiable_targets`：同时受产品支持、方案和授权约束的规范目标；
- `rollback_targets`：记录后状态仍匹配的已应用目标。

每次集合迁移记录理由和规则 ID，后续集合不能静默扩大前序边界。

### 8.2 平台 profile

平台 profile 是数据/契约而不是隐藏控制流，必须包含：

- 生态和平台版本兼容性；
- 发现根、文件名、链/覆盖行为、默认值与排除项；
- manifest/配置 schema 和未知字段策略；
- 支持的引用形式、基准位置、变量展开、路径/大小写语义；
- 上下文/列表限制、单位、加载阶段、顺序/截断行为与证据来源；
- 资料 URI/文档/版本、采集日期、profile 版本和评审状态。

只有与分析版本兼容的明确规则才能支撑推导证据。未知、不兼容或过期 profile 不能支撑
确定性胜者、schema 错误或预算 finding。结果记录 profile 和每项使用规则。更新 profile
属于规则集变化，可能改变案例指纹，不能静默发生。

### 8.3 引用解析

先做词法和元数据解析：读取受支持声明，以声明来源为基准，只展开版本支持的变量，在
允许根内规范化，判断目标类型，再检查获批元数据/内容。符号链接和大小写语义来自平台/
文件系统 profile。越界时不打开外部文件。瞬时 I/O 最终失败产生 `error`；解析语义不
支持或未知时拒绝判断/报相应配置结果，不猜目标。

### 8.4 上下文预算规则

确定性预算 finding 必须同时具备：正确单位/加载阶段的测量、兼容且有文档依据的限制与
顺序规则、该规则下的合格盘点，以及超限或实际截断。字节不能静默换算 token。分配未知
时只能记录盘点测量、候选或拒绝判断，不能给确定性 finding 或 pass。证据必须包含 profile
与测量血缘。

## 9. 语义分析与提供商边界

### 9.1 中立请求契约

语义请求只包含：

- 稳定问题/检查 ID 与分类法版本；
- 带来源句柄和位置的最小主张摘录；
- 保留的语气、例外、范围/区域、维度和见证；
- 确定性适用/优先级事实及证据句柄；
- 待比较问题、允许的输出词表；
- 引用句柄、提出替代解释并在缺证据时拒绝判断的要求。

请求排除原始凭证、环境转储、脚本正文、无关资源、摘录足够时的完整文件，以及披露清单
之外的内容。秘密检测/脱敏属于纵深防御，不能作为扩大同意范围的理由。

### 9.2 中立响应契约

适配器返回响应封装：请求/输入摘要、提供商/模型身份、可安全记录的请求 ID、适配器和
提示契约版本、按主张/区域/维度的候选关系、引用内容句柄、推理摘要、未知/替代解释与
响应校验状态。提供商置信度只作为其元数据，本地裁决器负责 Agent Doctor 置信度。

缺引用、非法标签、回显秘密或 schema 失败会使响应不可用，产生错误/脱敏事件而非
finding。提供商不得生成授权或可执行修复。

### 9.3 Manifest 授权与缓存策略

授权必须主动、且只适用于当前清单。用户显式发起的一键语义诊断只授权紧接着生成的
manifest；独立调用需要确认精确 digest。记录不含原始凭证；提供商、内容集合、用途、
模型、推理强度、适配器或提示契约变化后不能复用。提供商侧保留、训练、区域和缓存行为
在可知时披露；未知必须明确写未知。

默认关闭跨运行语义响应缓存。未来只有在用户主动启用并披露后，才可加入本地缓存；键
必须包含提供商/模型、适配器/提示契约、分类法、精确最小输入摘要和相关策略。缓存必须
遵守敏感与保留规则，不存原始凭证，不把缓存推断变成证明，任一键变化即失效。物理加密
与保留机制后续决定；提供商侧缓存属于提供商策略事实，不是 Agent Doctor 保证。

## 10. 带版本的概念结果模型

以下是代表性结构，不是物理 JSON schema 或实现：

```yaml
result_set:
  schema_version: "agent-doctor-result/0.1"
  result_id: 运行内结果ID
  run:
    id: 运行ID
    started_at: 时间
    completed_at: 时间
```

### 10.1 投影规则

- 终端突出范围、最高影响分组、覆盖缺口和下一步，并提供查看全部结果的路径；
- Markdown 是长期人工评审形式，含盘点、证据、裁决理由、版本和脱敏标记；
- JSON 保留完整概念图与机器枚举；
- CI 按明确策略评估封存结果，同时报告策略结果与执行/覆盖缺口；阈值只改变 CI 决策，
  不修改长期结果；
- 所有投影使用相同 ID 和轴值；本地化文案可以不同，语义不能改变。

## 11. 错误、部分结果、隐私与安全

### 11.1 错误和部分结果

- 错误限于最小诚实诊断单元；前置条件完整的独立检查继续；
- 组件诊断不能静默替代检查结果。例如解析失败记录执行错误；另一个因内容缺失的语义
  问题可以拒绝判断，并把该错误列为缺失前置条件；
- 重试有边界且有记录。受支持 resolver 的重试策略耗尽并真正满足分类条件前，瞬时失败
  不能称为无效引用；
- 部分解析输出携带完整性标志；规则声明必要前置条件，不能把部分输入当完整；
- 结果图不通过不变量校验时，不能宣传为完整规范结果，但保留可审阅局部诊断。

### 11.2 去重与分组

候选案例按问题、逻辑来源/主张、区域、维度、规则和版本规范化。完全相同者合成一个案例
并保留多个证据位置。同一用户交互可以成组，但不能通过删除来“调和”不同状态或互斥
标签。分组说明成员属于同一缺陷、因果/相关、潜在或不同维度。G-004 因而只有一个重复
安装 finding；G-018 只有一个含维度限定重复与冲突的分组。

### 11.3 隐私行为

- 报告默认使用工作区相对、最小化位置和最小决定性摘录，明确标记保留/脱敏内容；
- 秘密和原始凭证不得进入模型请求、报告、可能泄露它们的指纹、日志或变更记录；
- 默认不执行或提交脚本正文；本地检查存在性/元数据与读取内容分开；
- 文件被引用不代表应读取全文；每次读取仍由目的和范围决定；
- 恢复资料可能必须包含敏感旧内容，因此只保存在本地，由实现限制访问、披露保留策略，
  普通报告只保存引用；无法充分保护时该写入类型不受支持；
- 用户选择的外部输出可能含已披露摘录；CLI 在边界提示，但不能保证目的地保密。

### 11.4 安全与信任假设

Agent Doctor 诊断配置协调性，不替代恶意软件或供应链扫描器。为保护自身契约，它仍需
防御式解析、资源边界、不执行脚本、路径/链接检查、秘密最小化和不可信模型响应校验。
越界引用或不安全代码不能被扩张成“恶意意图”结论。配置内容无权指挥扫描器、请求网络、
改变范围或授权写入。
