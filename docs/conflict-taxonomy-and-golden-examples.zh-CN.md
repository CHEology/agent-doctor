## 1. 目的与边界

本文档定义什么是正确的 Agent Doctor 诊断。它是后续详细设计、测试和实现共同使用的
评审基线；不选择架构、存储格式、框架、模型提供商或算法。

本分类法明确以准确性为先。一个有用的结果可以是“未运行”“证据不足”，也可以是
“静态假设需要运行时验证”。静态证据永远不能证明未来一定会选择某个 Skill，也不能
证明某种运行时因果结果。

修复授权与回退仍以 PRD 为准。除非需要说明诊断后的下一步，本阶段不展开这部分内容。

## 2. 诊断单元与术语

### 2.1 诊断单元

最小裁决单元是一个**交互案例（interaction case）**：在已经声明的分析范围和适用
区域内，针对一个或多个配置主张提出的一个可独立评审的问题。

每个交互案例包含：

- 所选工作区、路径、配置模式及相关提示或任务区域，合称**分析范围**；
- 一个或多个**来源**，例如 Skill 清单、`SKILL.md`、适用的 `AGENTS.md`、覆盖文件、
  受支持配置值或直接引用资源；
- 来源中保持原始位置和限定条件的最小有意义**主张**；
- 这些主张可能共同约束同一请求的**实际适用区域**；
- 诊断问题、证据类型、检查状态、实质标签、严重程度、置信度和下一步验证方式。

诊断单元不一定是“一对文件”。一个用户可见的交互问题可能需要多个文件共同举证；
同一批文件中的两个无关问题则应拆成两个案例。实质相同的案例应合并，但保留所有证据
位置。

### 2.2 核心术语

| 术语 | 定义 |
| --- | --- |
| 主张（claim） | 经过规范化的义务、禁止、许可、触发条件、范围声明、输出约束、引用或配置断言，并与原文和位置绑定。 |
| 适用区域 | 某项主张可能生效的请求、路径、模式和条件。 |
| 实际主张 | 应用确定性的发现、范围和优先级规则后仍然适用的主张。 |
| 共享区域 | 两个或多个主张适用区域的交集。交集为空，表示在该范围内没有实际交互。 |
| 维度 | 主张发生交互的主题，例如必做动作、禁止动作、提问策略、输出形式、触发、引用有效性或上下文使用。 |
| 观察证据 | 直接读取到的事实：原文、路径、元数据、是否存在、是否可读、声明的配置或启用模式。 |
| 推导证据 | 由观察事实和有文档依据的规则可复现地得到的结论，例如实际范围、优先级、重复身份或对限制值的测量比较。 |
| 推断证据 | 无法由语法或平台规则必然推出的语义判断。模型输出如果没有独立验证，只属于这一类。 |
| 运行时证据 | 在已记录条件下实际执行产生的证据。MVP 推迟收集此类证据，但术语上必须保留该边界，避免把静态判断冒充运行时事实。 |
| 决定性证据 | 一旦缺失，就必须改变预期裁决或拒绝判断的最小证据。 |
| 问题关系 | 说明多个证据位置或标签共同描述同一个用户问题，而不是重复报警的关联。 |

### 2.3 三个相互独立的输出轴

每项完成的检查都使用三个独立输出轴，不能压成一个含义过载的标签：

1. **检查状态**沿用 PRD：`pass`、`finding`、`candidate`、
   `insufficient_evidence`、`not_run` 或 `error`；
2. **实质标签**描述关系或缺陷，例如 `semantic_conflict` 或
   `invalid_reference`；
3. **验证限定符**说明是否需要运行时证据，目前为
   `runtime_validation_needed`。

下文会把 `insufficient_evidence` 和 `not_run` 与实质类别一起完整定义，因为它们是
必需的裁决结果；但它们仍然是状态，不是语义冲突类型。
`runtime_validation_needed` 是限定符，不是问题已经成立的证据。

## 3. 证据、严重程度与置信度规则

### 3.1 证据规则

- 每个结果都必须引用观察证据；如果没有，也要明确说明原因；
- 确定性问题必须有观察事实和基于文档规则的可复现推导，模型断言本身不能满足要求；
- 语义问题必须指出参与比较的主张、共享区域、维度及从证据到标签的推理；
- 来源摘录遵循最小化和秘密保护原则；未获批披露的内容可以只记录位置；
- 平台行为假设必须注明版本或资料依据。无法确认所分析版本时，不得声称结论是确定性
  的。

### 3.2 严重程度与置信度

严重程度沿用 PRD 第 11 节，表示潜在影响，不表示确定性。置信度表示结论受到证据
支持的程度：

- **高：** 决定性证据完整，推导或语义解释在当前范围内没有合理的竞争性解读；
- **中：** 最有根据的解读已经足以报告，但仍存在合理的限定条件、隐含惯例或未观察
  条件；
- **低：** 假设值得提示，但仍有会改变结论的重要替代解释。

低置信度的实质问题通常使用 `candidate`。规则证据门槛已经满足时，`finding` 可以是
高或中置信度。对于 `insufficient_evidence`，置信度表示“确定当前证据不足”的把握，
不是对某个隐藏问题存在的把握。对于 `not_run`，实质结论的置信度不适用。

## 4. 分类法

静态可判定性分为三档：**是**表示完整的范围内静态事实和有文档依据的规则足以决定；
**有条件**表示部分实例可静态判定，但语义或版本相关实例不行；**否**表示所声称的结果
本质上需要执行证据。

### 4.1 `semantic_conflict`——真实冲突

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 两个或多个实际主张在非空共享区域内约束同一维度，并且无法全部满足，或全部满足会违反一项重要的明示约束。包括“必做/禁止”碰撞、不兼容的强制输出格式、矛盾的提问策略及互斥的适用要求。 |
| 排除条件 | 仅触发重叠；文风张力；重复措辞；应用优先级后只有一项实际生效；位于不同条件或维度且可共同满足；只有运行时竞争猜测但没有不兼容主张。 |
| 证据要求 | 主张原文与位置、共享区域证明、优先级分析、不兼容义务或禁止状态；若不兼容关系无法由语法直接得出，还需语义推理。 |
| 可能影响 | 违反重要约束或选错流程通常为 high；持续造成退化或不可预测通常为 medium；只有可能造成破坏性或未授权行为时才是 critical。 |
| 置信度处理 | 经过范围解析后的明确“必做/禁止”或逻辑不兼容可以高置信；术语、条件或重要性需要解释时为中或低置信，低置信只作候选。 |
| 常见误报 | 把“优先”当“必须”；忽略例外；比较互不重叠的目录；忽略有效覆盖；把不同输出章节误当互斥格式；假设两个 Skills 不能协作。 |
| 静态可判定 | 有条件。明确的文本逻辑冲突可静态判定；未来 Skill 选择或实际后果不可。 |

### 4.2 `scope_overlap`——范围重叠

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 两个或多个 Skill/指令存在可证明的非空适用或触发交集。该标签不表示行为不兼容或等价。 |
| 排除条件 | 用词相似但任务或路径互斥；应用排除条件后交集为空；来源在所选范围内不适用或未被发现。 |
| 证据要求 | 触发/范围主张、排除条件、所选路径与模式，以及一个位于共享区域内的明确见证请求或条件；可以确定时也要说明各自独有区域。 |
| 可能影响 | 单独出现通常为 info/low；触发过宽造成持续路由歧义时可为 medium；只有存在单独的冲突、重复或运行时风险结论时才提高影响。 |
| 置信度处理 | 明示范围交集为高置信；自然语言触发需要解释时为中/低。 |
| 常见误报 | 只匹配关键词；忽略负向触发；比较已安装但未激活的来源；认定通用 Skill 与专用 Skill 必然竞争。 |
| 静态可判定 | 有条件。明确路径/范围交集可静态判定，开放式自然语言触发不一定。 |

### 4.3 `behavioral_redundancy`——行为重复

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 在同一区域和维度内，一个实际来源相对另一个没有增加任何重要行为、约束或证据。相同标识或结构重复安装属于确定性子类；语义等价指令属于语义子类。 |
| 排除条件 | 同一主题但能力不同；通用规则加有价值的专门化；重复文字承担不同范围或权威边界作用；互补验证；只有重叠。 |
| 证据要求 | 重复身份、结构或规范化主张；共享区域；没有重要独立贡献的比较；以及可能使重复合理的范围/权威原因。 |
| 可能影响 | 通常为 low/medium，来源包括维护漂移、重复路由、噪声报警或上下文消耗。 |
| 置信度处理 | 完全或结构重复为高置信；语义等价通常需要校准解释，多为中置信。 |
| 常见误报 | 合并备用/降级指令；忽略更窄的验收条件；把翻译评审稿当作实际重复配置；把不同边界重复出现的安全约束当浪费。 |
| 静态可判定 | 有条件。身份和结构重复可静态判定，完整行为等价通常是语义判断。 |

### 4.4 `complementarity`——互补

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 实际主张共享适用区域，但各自提供不同且可共同满足的贡献，例如领域指导加输出验证。 |
| 排除条件 | 某项没有重要独立贡献；同一维度义务无法共同满足；从不共享区域；因为没有检查详细内容就默认兼容。 |
| 证据要求 | 共享区域、每项主张的独立贡献，以及明确的共同满足说明或见证。 |
| 可能影响 | 通常为 info 且有益，可解释为什么不应“修复”这类重叠；上下文成本仍可单独标风险。 |
| 置信度处理 | 职责和共同满足方式明确时为高；依赖隐含顺序或运行时选择时为中/低。 |
| 常见误报 | 把所有不冲突的重叠都叫互补；漏掉隐藏输出约束；从两个独立触发的 Skill 推断出编排；忽略使一方不生效的优先级。 |
| 静态可判定 | 有条件。逻辑兼容可以静态判定，实际协作或选择不能。 |

### 4.5 `precedence_override`——优先级/覆盖

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 有文档依据的发现、路径或优先级规则使一个来源/主张在特定范围内支配、遮蔽、替换或收窄另一个。它是中性关系，不自动表示缺陷。 |
| 排除条件 | 没有依据的“更具体者优先”假设；没有解决规则的同级矛盾；普通互补；不在适用发现链中的文件。 |
| 证据要求 | 来源链与位置、所选路径、适用且带版本的优先级规则，以及最终实际/非实际主张。 |
| 可能影响 | 有意覆盖为 info；意外改变流程或隐藏重要约束时为 medium/high。 |
| 置信度处理 | 只有发现和优先级可以确定时才可高置信；否则使用证据不足或候选，不能猜胜者。 |
| 常见误报 | 把文件距离当优先级；把展示顺序当权威；把已覆盖主张继续报告为同时生效；忽略目录边界。 |
| 静态可判定 | 是，前提是平台规则和完整来源链已知。 |

### 4.6 `invalid_reference`——无效引用

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 范围内声明的引用按受支持规则无法有效解析，因为目标缺失、不可读、格式错误、类型不受支持或逃逸允许范围。 |
| 排除条件 | 目标有效但语义过期；明确标为可选且确实可选的引用；只是不允许提交给模型但本地可解析；尚未完成重试的瞬时读取错误。 |
| 证据要求 | 声明原文和位置、规范化目标、适用解析/范围规则、存在性/可读性/类型观察结果。除非有效性依赖内容且允许检查，否则无需读取内容。 |
| 可能影响 | 必需指导无法加载时为 medium/high；真正可选材料为 low；越界引用还可能带来范围/隐私关注，但不应扩张为安全扫描结论。 |
| 置信度处理 | 解析器规则和文件事实完整时为高；否则为候选或 `error`。 |
| 常见误报 | 相对扫描进程而不是声明文件解析；大小写判断错误；未展开受支持变量；把模型披露排除误当成本地引用无效。 |
| 静态可判定 | 对受支持形式和可用元数据而言，是。 |

### 4.7 `stale_reference`——陈旧引用

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 引用可以解析，但决定性证据表明，它对于所支持的主张已经指向过时、已改名、被替代或版本不兼容的目标。 |
| 排除条件 | 缺失/越界目标（属于 `invalid_reference`）；只有文件年龄；有意固定且兼容的旧版本；仅偏好较新资源。 |
| 证据要求 | 可解析的声明和目标，加权威的当前名称/版本/契约，或能证明不匹配的内部矛盾。时间戳本身不是决定性证据。 |
| 可能影响 | 根据旧指导是否改变行为，可从 low 到 high。 |
| 置信度处理 | 明确版本/改名证据为高；强内部矛盾为中；低置信怀疑应拒绝判断。 |
| 常见误报 | 使用最后修改时间启发式；默认必须用最新版；忽略兼容声明；把历史示例当成实际依赖。 |
| 静态可判定 | 有条件。有当前契约或版本约束时可静态判断，否则新旧可能需要外部或运行时证据。 |

### 4.8 `context_budget_risk`——上下文预算风险

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 已证明受支持配置集合超过有文档依据的上下文/列表限制、被确定性截断，或有强证据表明占用足够多的有限上下文，可能影响发现或指令保留。 |
| 排除条件 | “文件看起来很长”；没有上下文后果的重复；泛化性能猜测；语义检查未运行。 |
| 证据要求 | 相关大小/数量测量、带版本的预算行为、启用范围，以及可用时的实际截断观察。限制或分配未知时，只能报告候选并写明假设。 |
| 可能影响 | Skill/指令可能被省略时通常为 medium；只有上下文债务而未证明省略时为 low；有重要指导丢失证据时才是 high。 |
| 置信度处理 | 测量超限或观察截断为高；估算压力为中/低。 |
| 常见误报 | 把字节等同 token；统计相关阶段不会加载的内容；依赖过期的平台限制；重复计算共享资源。 |
| 静态可判定 | 有条件。有文档限制的测量可静态判定；注意力、选择或结果退化需要运行时验证。 |

### 4.9 `configuration_risk`——配置风险

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 受支持配置值或必需元数据格式错误、不受支持、内部矛盾，或可证明地改变发现/范围并很可能导致预期指导缺失或误用。 |
| 排除条件 | 有效偏好差异；引用类问题；只有上下文风险；对未知键行为的无依据猜测；超出配置协调范围的安全漏洞。 |
| 证据要求 | 配置/元数据原文与位置、受支持 schema 或行为规则、解析/推导效果及受影响范围。 |
| 可能影响 | 维护警告为 low；指导被跳过或错用为 medium；重要必需流程被稳定禁用时为 high。 |
| 置信度处理 | schema 违规或有文档依据的不受支持声明为高；行为风险靠推断时降级为候选。 |
| 常见误报 | 使用错误产品版本的 schema；把未知但可前向兼容的字段当错误；忽略默认值；把 lint 偏好当无效元数据。 |
| 静态可判定 | 有条件。schema 和明示配置效果可静态判断，下游行为影响不一定。 |

### 4.10 `insufficient_evidence`——检查状态

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 问题在范围内且已经尝试检查，但一个或多个决定性事实、受支持规则、获批内容或明确含义不可用，因此无法负责任地判断为通过、实质问题或候选。 |
| 排除条件 | 检查被关闭/不可用（`not_run`）；执行失败（`error`）；低置信但有证据且值得提示的假设（`candidate`）；完整检查后无问题（`pass`）。 |
| 证据要求 | 检查过什么、缺少什么决定性证据、为什么重要，以及能够解决问题的最小下一步。 |
| 可能影响 | 未知。不能编造严重程度；有依据时可单独给出潜在影响范围。 |
| 置信度处理 | 可以高置信认定“证据不足”，但不表示对任何隐藏实质标签有高置信。 |
| 常见误报 | 用拒绝判断逃避可执行的确定性检查；完整检查后把“未发现问题”写成证据不足；同时又赋予可能冲突标签；把模型模式不可用与已尝试分析混淆。 |
| 静态可判定 | “应当拒绝判断”本身可静态决定，底层问题仍未决定。 |

### 4.11 `not_run`——检查状态

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 某项已定义检查因被关闭、不可用、超出已披露范围或当前模式不支持而没有尝试。必须写明原因和受影响检查。 |
| 排除条件 | 已开始但失败（`error`）；完成且无问题（`pass`）；已经尝试但缺决定性证据（`insufficient_evidence`）。 |
| 证据要求 | 运行配置、披露范围、能力可用性及具体跳过的检查族。无需实质来源证据。 |
| 可能影响 | 不声称存在问题，只说明覆盖缺口。 |
| 置信度处理 | 被跳过的实质结论不适用置信度；跳过原因本身应是观察或推导事实。 |
| 常见误报 | 把跳过语义分析写成通过；把解析器崩溃写成未运行；用一个模糊族级标记隐藏具体哪些检查执行过。 |
| 静态可判定 | 是，检查是否执行属于运行事实。 |

### 4.12 `runtime_validation_needed`——验证限定符

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 静态证据支持一个具体、可测试的假设，但用户可见结果取决于 Skill 选择、模型解释、动态输入、Hook 行为或其他执行事实。通常附在 `candidate` 上。 |
| 排除条件 | 已经构成 finding 的明确静态矛盾；没有可测试假设的模糊不确定性（应为证据不足）；检查未运行；笼统地希望多做测试。 |
| 证据要求 | 假设的静态依据、尚未解决的准确运行时命题、测试所需受控条件，以及确认/否定该命题的结果。 |
| 可能影响 | 沿用所假设风险的影响，但必须表述为潜在而不是已观察影响。 |
| 置信度处理 | 只衡量“需要验证”和假设本身的强度，绝不能表示未观察运行结果的确定性。该限定符不能把候选升级为 finding。 |
| 常见误报 | 添加到所有语义判断；把静态文本冲突说成纯运行时问题；暗示已经具备运行时收集能力；没有可证伪命题。 |
| 静态可判定 | 运行时命题本身否；识别静态证据无法决定它，是。 |

### 4.13 `no_material_relation`——黄金集对照标签

| 属性 | 规范 |
| --- | --- |
| 纳入条件 | 完整检查后，参与比较的范围内来源没有共享适用区域，或在所问维度没有重要关系。仅用于黄金反例，不作为问题 finding 输出。 |
| 排除条件 | 存在任何受支持的实质关系；检查不完整；含义未解决。 |
| 证据要求 | 完整的相关范围/主张比较，以及互斥区域或无关维度。 |
| 可能影响 | 对所问问题无。 |
| 置信度处理 | 确定性互斥为高；否则使用证据不足。 |
| 常见误报 | 把未知当无关系；漏掉嵌套范围；只查关键词不查意图。 |
| 静态可判定 | 有条件。 |

## 5. 裁决程序

### 5.1 有序程序

1. **固定问题与范围。** 记录工作区/路径、受支持来源、运行模式、排除项、平台/规则
   假设和待裁决维度。
2. **确认执行状态。** 未尝试则返回 `not_run`；无法完成则返回 `error`。二者都不能
   当成配置本身的证据。
3. **收集并区分证据。** 保留观察位置和摘录，分开记录推导、推断及运行时证据。
4. **先处理确定性有效性。** 在比较语义行为之前，先裁决引用/配置缺陷、发现、实际
   范围和优先级。
5. **验证共享适用性。** 用见证证明非空共享区域；如果完整检查后交集为空，则对该问题
   使用 `no_material_relation`；无法建立共享区域时拒绝判断。
6. **逐维度比较。** 判断实际主张是不兼容、重要行为等价、各有作用且能共同满足，还是
   仅仅范围重叠。
7. **分开静态结论与运行时假设。** 只陈述证据已证明的内容。执行才能决定且可测试时，
   给候选附加 `runtime_validation_needed`。
8. **独立赋予状态、标签、严重程度和置信度。** 解释影响依据和每次置信度降级。
9. **合并重复证据。** 描述同一交互的多个位置应分组；可独立回答的问题或区域仍应拆分。
10. **做反例检查。** 定稿前写出最强的合理非问题解释，并说明证据为什么排除了它；无法
    排除时降级或拒绝判断。

### 5.2 多标签规则

- `scope_overlap` 可以与 `semantic_conflict`、`behavioral_redundancy` 或
  `complementarity` 共存：前者描述共享区域，后者描述区域内行为；
- `precedence_override` 可以与 `scope_overlap` 共存。只有应用优先级后仍存在未解决的
  实际冲突，或报告明确把文本冲突标成潜在而非实际时，才可同时出现冲突；已经解决的
  矛盾不是实际 `semantic_conflict`；
- `context_budget_risk` 或 `configuration_risk` 可以和语义关系共存，因为回答的是不同
  维度；
- 对相同主张、区域和维度，`semantic_conflict`、`behavioral_redundancy` 与
  `complementarity` 互斥。只有分别注明不同维度或子区域时，才能出现在同一分组报告；
- 对同一诊断问题，`insufficient_evidence` 不能与 `finding` 共存；若一个维度可判断而
  另一个不可，应拆成问题；
- `not_run` 对被跳过的检查是排他的，同一运行中的其他检查族仍可有 finding；
- `runtime_validation_needed` 通常限定 `candidate`，绝不能用缺失的运行证据制造 finding。

### 5.3 何时拒绝判断

以下任一决定性条件未解决时使用 `insufficient_evidence`：

- 适用来源链不完整或不可读；
- 必须比较的内容未获批检查；
- 解决发现或优先级所需的平台/版本规则未知；
- 无法给出可信的共享区域见证；
- 重要术语存在两种会改变标签的合理解释；
- 陈旧怀疑只有文件年龄支持；
- 怀疑上下文压力但没有已知或可观察的预算依据；
- 评审分歧会改变标签，且无法用已记录证据解决。

拒绝判断必须指出缺失事实和取得它的有限步骤。如果静态证据本来就不可能决定命题，
则应改为一个可测试候选并附 `runtime_validation_needed`。

### 5.4 黄金标签的人工评审规则

评审者核对来源摘录、适用区域、决定性证据、预期状态/标签和禁止误分类后，案例才算
**已评审**。有争议的案例不能进入获批黄金集，除非达成共识，或把预期结果改成明确的
拒绝判断。阶段 04 将定义抽样、评估者独立性和测量方法。

## 6. 黄金样例规范

以下 schema 是测试数据与评审的概念契约，不选择物理存储技术。

| 字段 | 必填内容 |
| --- | --- |
| `id` | 稳定样例 ID。 |
| `title` | 简短名称。 |
| `case_kind` | `positive`、`negative` 或 `boundary`。正例预期存在实质问题；反例要求完整检查不能虚构问题；边界例检验不确定性、优先级或相邻类别。 |
| `taxonomy_version` / `schema_version` | 标注所用版本。 |
| `prd_refs` | 相关需求与验收标准。 |
| `scope` | 路径/工作区、适用条件、来源类型、排除项和平台/规则假设。 |
| `analysis_modes` | 确定性和语义模式的启用、关闭或不可用状态。 |
| `inputs` | 裁决所需的最小来源 ID、类型、位置及原文/元数据。 |
| `question` | 一个可独立评审的诊断命题。 |
| `expected` | 检查状态、实质标签、验证限定符、严重程度、置信度、证据类型和静态可判定性。 |
| `rationale` | 预期结果为什么成立、最接近的替代分类为什么不成立。 |
| `decisive_evidence` | 决定标签的最小证据。 |
| `acceptable_uncertainty` | 不会使预期结果失效的变体/未知，以及允许的置信度范围。 |
| `prohibited_misclassification` | 不可接受的结果，尤其是强行 pass/finding、把相似当冲突、把静态判断冒充运行事实。 |
| `review_status` | `draft`、`reviewed`、`disputed` 或 `retired`；样例物化时还要记录评审者和日期。 |

黄金样例必须尽可能精简，以暴露决定性边界，但不能删除影响范围或语气强度的限定条件。
若脱敏删除的限定词会改变答案，该样例无效。

## 7. 已评审的代表性样例集

这些是规范性说明样例。“已评审”表示通过第 9 节内部一致性检查；它们还不是已经物化
的评测语料，也不是阶段 04 的测量方案。

除非另有说明，所有来源均可读且在所选范围内；摘录对所问问题完整；确定性检查已启用；
不存在运行时轨迹。

### G-001——明确的必做/禁止碰撞

- **类型/PRD：** 正例；P1-R2、P1-R3、P0-R11–R14；AC-3、AC-5、AC-7。
- **输入：** `AGENTS.md:12` 要求“更新依赖时，回复前运行测试”；
  `skills/fast-update/SKILL.md:31` 要求“更新依赖时不得运行测试，立即返回清单改动”。
- **问题：** 两项实际动作策略能否共同满足？
- **预期：** `finding`；`scope_overlap` + `semantic_conflict`；high；高置信；观察+
  推导证据；文本冲突静态可判定。
- **理由/决定性证据：** 同一个“更新依赖”见证同时要求和禁止测试，且没有规则使一方
  优先。
- **可接受不确定性：** 不知道 Codex 是否选择该 Skill，不影响“两者都实际生效时”的
  文本冲突。
- **禁止：** 判为重复、互补、通过，或声称运行时确实跳过了测试。

### G-002——兼容的输出章节，不是格式冲突

- **类型/PRD：** 反例；P1-R2、P1-R3、P1-R6；AC-5–AC-7。
- **输入：** 一条要求“以一句结果开头”，另一条要求“以 Sources 章节结尾”。
- **问题：** 两项输出要求是否不兼容？
- **预期：** `pass`；`complementarity`；info；高置信；观察+推断；共同满足静态可判定。
- **理由/决定性证据：** 一个回复可以同时满足首尾约束，且两者贡献不同。
- **可接受不确定性：** 中间正文没有限定。
- **禁止：** 仅因都约束输出就判 `semantic_conflict`。

### G-003——通用与专用 Skill 共享触发

- **类型/PRD：** 边界例；P1-R1、P1-R3、P1-R6；AC-6、AC-7。
- **输入：** A 处理“创建或编辑文档”；B 处理“保留修订痕迹地红线审阅 `.docx` 合同”；
  “红线审阅这份 `.docx` 合同”同时适用。正文职责不同且无互相禁止。
- **问题：** 静态证据能说明什么关系？
- **预期：** `candidate`；`scope_overlap` + `complementarity`；仅“路由可能选中较不专用
  Skill”的假设附 `runtime_validation_needed`；潜在影响 medium；中置信；有条件可判定。
- **理由/决定性证据：** 见证证明重叠，正文证明贡献不同且兼容；实际选择/协作是运行
  命题。
- **可接受不确定性：** 路由假设可被否定而不改变静态重叠。
- **禁止：** 实际冲突、保证会错路由，或把运行命题写成 pass。

### G-004——结构上重复安装的 Skill

- **类型/PRD：** 正例；P0-R6、P0-R10、P0-R15；AC-2、AC-3。
- **输入：** `skills/pdf/SKILL.md` 与 `vendor/skills/pdf/SKILL.md` 声明相同标识，规范化
  清单/内容摘要相同，且都被发现。
- **问题：** 两次安装是否增加不同的重要行为？
- **预期：** `finding`；`scope_overlap` + `behavioral_redundancy`；medium；高置信；观察+
  推导；静态可判定。
- **理由/决定性证据：** 相同标识、结构和实际发现构成确定性重复子类。
- **可接受不确定性：** 加载顺序可未知，重复仍成立。
- **禁止：** 产生两条同义报警、只用语义证据、因路径不同判互补。

### G-005——主题相似但职责不同

- **类型/PRD：** 反例；P1-R1、P1-R3；AC-5–AC-7。
- **输入：** A 从 PDF 提取表格，B 校验已有表格中的算术；见证要求提取表格并核对合计。
- **问题：** 主题相似是否证明重复或冲突？
- **预期：** `pass`；`scope_overlap` + `complementarity`；info；高置信；推断证据；有条件
  可判定。
- **理由/决定性证据：** 产出和职责不同，并能为见证请求组合。
- **可接受不确定性：** 未规定执行顺序。
- **禁止：** 因共同出现“表格”判重复，或因两个 Skill 同时适用判冲突。

### G-006——确定性的嵌套覆盖解决矛盾

- **类型/PRD：** 边界例；P0-R3、P0-R9、P1-R3；AC-2、AC-7。
- **输入：** 根指令要求报告使用 Markdown；`repo/api/` 的嵌套覆盖明确说“在本子树替换
  根格式规则，使用 JSON”；所选文件位于该子树，平台规则支持这种替换。
- **问题：** 所选路径是否仍有实际格式冲突？
- **预期：** 对实际冲突为 `pass`；`precedence_override`；info；高置信；观察+推导；
  静态可判定。
- **理由/决定性证据：** 有文档依据的来源链使 JSON 成为该维度唯一实际规则，根文本
  矛盾是潜在而非同时生效。
- **可接受不确定性：** 不声称运行时一定遵守 JSON。
- **禁止：** 报实际冲突，或假设根规则仍同等生效。

### G-007——猜测同级指令的优先级

- **类型/PRD：** 边界例；P0-R3、P0-R11–R14、P1-R6；AC-6、AC-7。
- **输入：** 两条同范围主张分别强制 YAML 和 JSON，但样例缺少决定胜者所需的顺序/
  权威规则。
- **问题：** 哪一条生效？
- **预期：** `insufficient_evidence`；没有胜者标签；不赋严重程度，可说明潜在 high；
  对拒绝判断为高置信；补齐规则后才可静态决定。
- **理由/决定性证据：** 同时生效时文字矛盾，但本题问优先级，决定性平台/来源链事实缺失。
- **可接受不确定性：** 可另保留“若两者都生效则存在冲突”的有条件候选。
- **禁止：** 虚构覆盖、无条件实际冲突 finding 或 pass。

### G-008——缺失的必需资源

- **类型/PRD：** 正例；P0-R4、P0-R7、P0-R10；AC-1–AC-3。
- **输入：** `SKILL.md:18` 要求审阅前读取 `references/policy.md`；支持相对声明文件解析，
  但目标不存在。
- **问题：** 引用是否有效？
- **预期：** `finding`；`invalid_reference`；medium；高置信；观察+推导；静态可判定。
- **理由/决定性证据：** 必需的受支持相对引用解析到缺失目标。
- **可接受不确定性：** 尚未运行验证行为后果。
- **禁止：** 判 `stale_reference`、`not_run`，或相对进程工作目录解析。

### G-009——没有新旧契约时只有旧时间戳

- **类型/PRD：** 反例；P0-R11–R14、P1-R6；AC-6。
- **输入：** 有效引用解析到 `policy-v2.md`，修改时间为两年前；范围内没有要求版本、改名、
  不兼容或权威当前目标。
- **问题：** 引用是否陈旧？
- **预期：** `insufficient_evidence`；不得报 `stale_reference`；对拒绝判断为高置信；静态
  未决。
- **理由/决定性证据：** 文件年龄不能证明内容对声明契约已经过时或错误。
- **可接受不确定性：** 后续版本注册表可决定此问题。
- **禁止：** 只凭 mtime 报陈旧，或以 pass 保证它仍新鲜。

### G-010——可解析引用中的明确版本不兼容

- **类型/PRD：** 正例；P0-R7、P0-R10、P0-R11；AC-2、AC-3。
- **输入：** Skill 元数据要求策略 schema 3；引用文件声明 schema 2 且“与 schema 3 不
  兼容”。
- **问题：** 该引用是否适合声明用途？
- **预期：** `finding`；`stale_reference`；high；高置信；观察+推导；静态可判定。
- **理由/决定性证据：** 目标存在，所以不是无效；明确不兼容证明它对该使用者已经过时。
- **可接受不确定性：** 不评价 schema 2 对其他使用者是否有效。
- **禁止：** 判无效引用、使用年龄理由，或用笼统配置风险替代精确标签。

### G-011——引用逃逸已披露工作区

- **类型/PRD：** 正例；P0-R1、P0-R7、P0-R29；AC-1、AC-3、AC-15。
