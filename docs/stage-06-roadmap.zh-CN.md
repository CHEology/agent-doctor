# Stage 06 — 模型辅助与持续诊断路线图

## 状态

提案。本文件不会覆盖已经批准的 Stage 01–04 契约，也不表示已经达到发布条件。

经过评审的模型路由基础及执行计划现已写入
[语义诊断与 OpenAI 模型路由详细设计](stage-06-semantic-and-model-routing-design.zh-CN.md)。
路由基础和本地开发性 Codex Desktop 提供商路径已经实现；提供商资格验证、长期
baseline 和发布测量仍未完成。

## 目标

补全混合式产品：确定性证据采集和最终裁决继续在本地完成；在此基础上加入经过资格
验证、按清单明确同意的语义分析路径，并让诊断可以长期重复运行，同时不默认披露或
修改用户的 Skill 集合。

## 里程碑

### 06.1 语义披露与提供商边界

本地开发性 Codex Desktop 路径已经实现；资格验证和受保护真实 canary 证据仍待完成。

- 通过已评审且新鲜的能力 profile 解析模型；官方推荐、账号可用、用户策略和产品资格
  必须分别表示。
- 生成精确披露清单，写明提供商、模型、用途、最小化内容句柄、排除项、保留/缓存
  事实及契约版本。
- 同意必须绑定清单摘要；提供商、模型、内容或用途变化后，同意与缓存键立即失效。
- 排除秘密和脚本/可执行正文，校验适配器生命周期和响应 schema，要求引用已披露
  句柄，并把所有可接受的模型陈述保留为 `inferred` 证据。
- 使用确定性的有界问题计划、隔离的分析者，以及在全新上下文中逆序读取来源的批评者。
  面板分歧必须弃权，不能用多数票掩盖。

### 06.2 本地裁决并写入唯一结果图

- 提供商关系只是候选假设；只有本地分类法和反例规则可以把经校验证据裁决为
  candidate、finding、pass 或 abstention。
- 分类、反例、适用性、严重度、置信度、去重和分组都由本地规则决定。
- 检查状态、实质标签和运行时限定维持三个独立轴。
- 提供商失败必须成为可见的部分结果，不能抹掉确定性结果图。
- 建议种类必须封闭且与标签兼容。被接受的建议仍然是 `authority=none` 的手工动作，
  必须写明收益、风险和验证；模型输出永远不能授权写入。
- 把封存图投影为人类优先的报告，逐 Skill 展示有边界的健康维度，并明确标出未知或尚未
  实现的部分。

### 06.3 长期增量诊断

- 基于稳定 ID 和输入修订清单，加入本地 baseline 与 delta 命令。
- 区分新增、已解决、证据变化和不可比较的 case。
- baseline 默认只保存在本地；导出内容必须是经过审阅的脱敏摘要。
- 支持定时本地运行，但不自动修复。

### 06.4 测量与资格验证

- 执行 Stage 04 的 holdout、独立标注、有用性、校准、隐私、重复性和性能协议。
- 每个提供商/模型/适配器/提示契约分别验证资格。
- 只有样本充分且所有绝对门禁通过后，才能发布准确率或发布就绪声明。
- 自动检测官方模型文档漂移，但新默认值只能通过已评审的 profile 变更和重新资格验证
  晋升。

### 06.5 安全的仓库集成

- 每个 PR 都运行确定性仓库检查。
- 模型代码审查保持 advisory，并与产品语义证据分离。
- 私有 runner 只能在明确 opt-in 后生成脱敏 delta，绝不让不可信 PR 代码接触个人
  home。
- 在授权、竞态安全 apply、验证、at-most-once 记录和 rollback 矩阵全部通过前，
  修复仍然只能 proposal/manual-only。

## 完成条件

只有当语义路径能够生成同一个有效封存结果图、所有适用的语义/隐私场景均可执行、
提供商资格可归因、本地 baseline 可复现，并且 Stage 04 测量协议（而不是实现者信心）
支持相应质量声明时，Stage 06 才算完成。

前两个条件目前已有本地开发性覆盖，包括全部 18 个 S-SEM 契约。资格验证、长期
baseline 和测量仍未完成，因此 Stage 06 仍未结束。
