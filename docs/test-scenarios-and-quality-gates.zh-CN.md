## 1. 目的、状态与边界

阶段 04 的目的，是让阶段 01–03 已确认的行为可以被验证。本文定义 Codex-first 本地
CLI MVP 的测试策略、带版本场景契约、物化黄金语料、扩展场景矩阵、测量协议、发布门禁、
测试数据治理、环境控制、失败产物和追踪关系。

本阶段不实现 Agent Doctor，不选择测试框架或 CI 服务，不打包 CLI，不认证真实模型
提供商，也不声称任何产品目标已经达到。`test-spec/` 下的物化文件是测试数据与契约，
不是测试运行器或产品代码。

以下约束继续生效：

- 诊断默认只读，确定性诊断离线执行；
- 语义覆盖默认开启且可关闭或缩小；用户显式要求完整诊断时，在同一精确 manifest 下
  运行两个盲审分析者和一个仲裁者，提供商证据仍须最小化并由本地裁决器最终决定；
  精确选择后不足两个 Skill 时应封存“不适用”结果且零提供商调用，不得暗中扩大范围；
- 静态证据永远不能证明运行时 Skill 选择或因果关系；
- 检查状态、实质标签与验证限定符彼此独立；
- 未知、保留不读、关闭或失败的工作不能变成 `pass`；
- 终端、Markdown、JSON 与 CI 使用同一份封存结果图；
- 每种受支持写入都必须经过精确预览、边界授权、稳定前置条件、受保护旧状态、验证、
  可归因记录、撤销/过期复核、最多一次执行和无法安全时拒绝回退。

### 1.1 阶段 04 假设

1. 阶段 01–03 英文文档是规范文本，中文文档是完整评审稿；
2. 阶段 02 样例具有规范性。物化时可以增加执行元数据，但不能削弱、重标或删除决定性
   证据；
3. 后续运行器能够实例化测试数据定义的虚拟文件、生成式来源清单、受控提供商响应、
   时钟、能力 profile 和故障屏障；
4. 依赖平台行为的确定性结论只有在 profile 已评审且兼容时才可执行。合成 profile
   只能测试契约，不能认证当前 Codex 行为；
5. 具体修复类型只有在阶段 05 选定，并在所有声称支持的文件系统能力 profile 上通过
   完整安全矩阵后，才算受支持；
6. 黄金物化中的“已评审”只表示阶段 02 规范性评审和阶段 04 物化内部评审，不表示已
   完成独立资格评估或达到统计充分性。

### 1.2 明确推迟的选择

阶段 05 才选择测试语言/框架、运行器布局、解析/断言/性质测试库、进程隔离方式、CI
厂商、数字退出码、提供商/模型清单、提示契约措辞、录制回放格式、真实平台 profile、
具体修复允许列表、文件系统原语、受保护恢复存储、摘要/规范化算法、性能 SLO 和产品
结果 schema 的物理序列化。

推迟不等于可以削弱测试 oracle。任何框架都不得让模型输出直接成为事实、使用环境路径
代替显式路径、隐藏局部覆盖，或因为某个平台原语实现麻烦就跳过变更前置检查。

## 2. 测试原则与 oracle

### 2.1 原则

1. **先契约，后实现。** 测试断言产品行为和组件边界，不绑定私有类或代码布局；
2. **每个计分单元只问一个问题。** 冻结一个检查、一个适用区域和一个维度；分组另计；
3. **正向与负向断言都必须精确。** 每个场景同时写明允许结果和禁止分类、读取、写入、
   泄漏及运行时声明；
4. **失败必须带类型。** 开始前关闭/不可用、开始后失败、缺决定性证据、策略失败和运行
   执行失败使用不同 oracle；
5. **证据来源属于正确性。** 标签即使表面正确，只要证据类型错误，测试仍失败；
6. **安全场景零容忍。** 授权、披露、并发、回退和秘密排除不能被准确率平均值抵消；
7. **按规范语义比较确定性。** 运行 ID、时间、可安全记录的请求 ID 与渲染文案可变；
   稳定身份、血缘、盘点、状态、标签、限定符、覆盖和变更记录不可变；
8. **禁止生产数据。** 资格评估只使用已评审合成输入与假秘密哨兵。

### 2.2 Oracle 优先顺序

资料冲突时按以下顺序处理：

1. PRD 中规范产品行为与验收标准；
2. 阶段 02 分类法、裁决规则和 G-001–G-020 精确预期；
3. 阶段 03 架构决定、组件契约与安全不变量；
4. 场景的精确 oracle 及其引用的兼容 profile；
5. 规范文件系统快照、提供商脚本、时钟、同意/授权记录、方案/变更记录和封存结果图；
6. 由结果图生成的各渲染与 CI 决定。

测试数据如果与 1–3 冲突，应判为 fixture/oracle 缺陷，不能为了让测试通过而修改产品
语义。模型输出本身永远不是 oracle。

### 2.3 主要风险与控制

| 风险 | 阶段 04 控制 |
| --- | --- |
| 把 20 个样例当成充分评测 | 分开规范回归集与更大的独立资格集，并规定最低样本量。 |
| 用候选/拒绝判断隐藏漏报 | 单独计算精确状态；候选/拒绝不能获得 finding 真阳性。 |
| 把静态证据写成运行时事实 | 禁止结果断言与运行限定符性质测试。 |
| 平台规则静默过期 | 覆盖兼容、未知、陈旧、不兼容 profile 及来源门禁。 |
| 各渲染快照变成独立诊断 | 全部与同一封存结果图做语义对比。 |
| 语义测试泄露评测内容或秘密 | 合成数据、holdout 隔离、清单同意、哨兵扫描、默认无跨运行缓存。 |
| 变更测试破坏开发工作区 | 每案例独立根、能力控制、前后清单与清理验证。 |
| 竞态测试变成靠时间的 flaky 测试 | 在命名屏障处确定性注入并发变化。 |
| 汇总指标掩盖某类/某组失败 | 分类别/profile 分层、精确状态矩阵、成员计分和零容忍门禁。 |

## 3. 带版本的场景与 fixture 契约

阶段 04 的物理契约是
[`scenario-suite.schema.json`](../test-spec/schema/scenario-suite.schema.json)，版本为
`agent-doctor-test-scenario/0.1`。必填语义改变时必须发布新 schema 版本。已发布场景 ID
保持稳定；决定性输入或预期改变时增加 fixture 版本，按黄金变更评审，不得原地静默覆盖。

每个场景显式包含：

| 范围 | 必填内容 |
| --- | --- |
| 身份 | 稳定 ID、标题、schema/fixture 版本、层级、极性/类型与测试族。 |
| 追踪 | PRD、AC、分类法、架构和门禁引用。 |
| 规则上下文 | 平台 profile、规则集，以及兼容/未知/陈旧/不兼容状态。 |
| 模式与边界 | 确定性/语义/修复模式；所选区域；分开的发现、检查、语义披露和修改边界；精确的一键或独立 manifest 授权。 |
| 前置与输入 | 合成虚拟文件及策略、精确生成器、配置、提供商脚本、受控时钟和计划故障。 |
| 刺激 | 命名组件契约与执行步骤。 |
| Oracle | 单一问题、决定性证据、理由、可接受不确定性和最强反例。 |
| 诊断预期 | 精确检查状态、标签、限定符、严重/潜在严重程度、置信度及适用规则。 |
| 证据与覆盖 | 允许证据类型、精确盘点状态/包含/排除、必需检查族、缺口和运行结果。 |
| 输出与变更 | 终端/Markdown/JSON/CI 断言；方案/应用/回退状态和精确写入文件数。 |
| 负向断言 | 禁止分类、读取、披露、写入、声明或状态迁移。 |
| 隔离与评审 | 清理边界和后置条件；草稿/已评审/有争议/已退役状态、评审者与日期。 |

`not_applicable` 仅是测试规范用于修复、渲染、隐私等非诊断契约测试的哨兵，防止人为
制造产品 `pass` 或 `finding`。它不属于 Agent Doctor 结果 schema，绝不能作为检查
状态输出。

该 schema 支持虚拟文件、确定性生成器和命名故障屏障，但不选择实现语言、运行器、
数据库、摘要算法或断言库。

## 4. 测试层与所有权边界

| 层级 | 主要组件/契约 | Oracle 与禁止越界 |
| --- | --- | --- |
| L0 schema/不变量 | 结果装配、证据账本、结果/变更记录 | 封闭枚举、三轴、血缘、多标签和操作状态；只能拒绝非法图，不能修补或重新裁决。 |
| L1 解析/规范化 | `ReadSource`、`ParseAndNormalize` | 同字节/版本产生等价主张和精确位置；保留语气、排除、原文；解析器不判语义关系。 |
| L2 发现/解析 | `PlanScope`、`Inventory`、`ResolveReference`、`ResolveApplicability`、profile 注册表 | 完整盘点、边界分离、相对声明来源解析、带版本优先级/预算/schema；不猜规则、不越界读。 |
| L3 确定性规则 | `RunDeterministicCheck` | 观察事实加兼容命名规则离线复现；不调模型，不把局部前置当完整。 |
| L4 语义边界 | `BuildSemanticDisclosure`、`RunSemanticCheck`、协调器/适配器 | 精确 manifest 授权、两个真实并行的盲审分析上下文、之后启动的全新仲裁上下文、最小句柄、封闭关联/引用、推断来源和生命周期；提供商不能定最终状态/严重程度/权限。 |
| L5 本地裁决 | `Adjudicate`、反例、拒绝、置信度 | 按分类顺序及主张/区域/维度键裁决；不抹上游错误，不升级推断证据。 |
| L6 身份/分组/输出 | `GroupCases`、结果装配、`Render`、`EvaluateCI` | 稳定无损分组；四种输出同源；策略失败与执行失败分开；渲染器不运行检查。 |
| L7 方案/授权 | `ProposeRepair`、`ValidateAuthorization` | 可回退允许列表、精确预览/摘要、目标/操作/会话/时间/撤销、单次确认；选择或同意不授权。 |
| L8 应用/验证/回退 | `ApplyProposal`、`VerifyChange`、`RollbackChange`、账本 | 全目标预检、目标内竞态保护、旧状态、失败即停、精确验证、最多一次、安全拒绝；不静默重规划/合并。 |
| L9 隐私/信任 | 范围守卫、内容代理、提供商边界、输出端、恢复存储 | 确定性零网络；不泄露/执行秘密脚本；被分析内容不能改策略或授权。 |
| L10 兼容/资格 | profile、独立版本字段、环境能力矩阵、完整流程 | 输入清单、兼容来源、重复运行、独立真值和发布门禁；不选择技术。 |

组件测试使用契约刺激和类型化值；集成测试验证所有权之间的迁移；系统/资格测试验证
用户可见全流程，但不允许下游静默“修好”上游违约。

来源及操作失败只作为生命周期事实，不能被当作配置有效/无效证据。

## 7. 变形、性质与对抗不变量

性质运行器可以生成更多样例，但 shrink 后仍须保留决定性限定词、范围、同意、profile
和事件顺序。

| 性质 | 必须保持的关系 |
| --- | --- |
| 渲染独立 | 改变终端/Markdown/JSON/CI 不改变诊断轴、ID、血缘、分组和覆盖。 |
| 人工证据可见 | 每个展示的 finding/candidate 都说明判断依据，并展示带位置的有界来源原句、存在时的推断面板理由和反例状态。终端截断保留最严重项及代表性最轻项并报告精确省略数量；未回答的语义问题不得写成风险。 |
| 无关顺序独立 | 来源、目录枚举或等价 map 重排不改变规范结果。 |
| 范围单调 | 冻结范围外增加来源不能新增范围内案例或读取。 |
| 证据单调 | 删除/保留决定性证据不能得到更强状态、严重程度、置信度或证据类型。 |
| 来源不可升级 | 一个或多个模型同意不能把推断变成观察/推导/运行证据。 |
| 优先级正确 | 兼容规则解决矛盾后不能留下实际冲突。 |
| 失败状态正确 | 没有新完成检查时，not-run/证据不足/error 不能转 pass。 |
| 同意/授权不扩张 | 解析、路径规范化、大小写折叠、变量展开或 canonicalization 不能扩大披露/修改权。 |
| 方案不可变 | 目标、操作、精确 diff、前置、身份或摘要变化后必须重新预览和授权。 |
| 应用身份 | 来源版本、目标身份/路径、授权状态、会话或时间变化阻止写入。 |
| 回退身份 | 后状态、身份、路径或反向授权变化阻止恢复，不允许自动 merge。 |
| 最多一次 | 重放确认、应用尝试或完成回退只返回记录，不产生第二次变更。 |
| 分组无损 | 去重/重排不能删除成员、区域、维度、状态和证据位置。 |
| 版本敏感 | 运行时易变字段不影响 ID；决定性契约/profile/主张变化不能静默沿用旧 ID。 |

对抗输入包括路径穿越、符号链接/inode 交换、大小写歧义、不支持变量、指挥扫描器/模型的
文本、秘密回显、畸形提供商封装、摘要重放、时钟跳变、操作间撤销、应用/回退并发变化和
输出目的地失败。

## 8. 测量协议

### 8.1 语料与计分单元

维护三个互相隔离的集合：

- **开发集：** 实现与调试可见；
- **规范回归集：** G-001–G-020 和安全契约回归；
- **资格 holdout：** 独立评审，产品/提示调优不可见，只在获批资格运行中计分。

主要诊断计分单元是一个 `(fixture 版本、检查 ID、问题、主张集合、适用区域、维度)`
交互案例。多维组按维度分别计算类别决定；可行动性按一个用户可见组计一次。文件和原始
报警行不是计分单元。

盘点以一个预期受支持来源出现及其状态为一单元；渲染一致性以每个案例/组的一个规范
语义字段为一单元；修复安全对操作尝试和每个目标迁移做精确断言，不用诊断准确率平均。

### 8.2 真值与评审独立性

1. 两名合格评审者独立标注资格案例；看不到 Agent Doctor/提供商输出及对方标签；
2. 完整核对决定性内容、范围、profile 兼容、语气/排除、区域、维度、三轴、严重程度、
   置信度规则、不确定性和禁止结果；
3. 第三名裁决者依据规范文本解决分歧；无法解决且会改变标签时，改为明确证据不足或不
   进入资格集；
4. 记录 fixture 作者、产品/提示调优者与最终评审者；作者不能成为自己案例唯一真值评审；
5. 真值变更发布新 fixture 版本并保留旧决定历史。

### 8.3 确定性计分

只有合格确定性规则针对准确问题输出 `finding`，才算预测阳性：

```text
precision = TP / (TP + FP)
recall    = TP / (TP + FN)
```

- 标签正确但区域/维度、证据类型或 profile 错误，不算 TP；
- 对预期确定性 finding 输出 candidate/证据不足，计 FN，不给部分 TP；
- 对预期反例输出 candidate 不计 finding FP，但计精确状态错误和候选误报率；
- 必需检查 not-run/error 使该资格运行对应检查族无效，不算真阴性；
- 预期拒绝、not-run、error 在独立的精确状态/原因矩阵计分，不混入普通反例分母。

只有独立数据充分时才评 AC-2：总体至少 200 个可计分确定性决定；每个将发布的 P0
规则族至少 30 个正例和 30 个反例/最近边界；包含每个声称支持的文件系统/profile 能力
及全部 critical 预期。报告点估计与 95% Wilson 区间。发布目标是 precision/recall 均
至少 95%，且 critical 漏报为零。本文不声称已经达到。

### 8.4 语义计分

语义预测阳性必须是本地裁决器对准确标签、区域、维度输出 `finding`。解释性 pass、
candidate 和证据不足都不是阳性。

- 预期 finding 被降为 candidate 时，在 finding recall 中计 FN，候选质量另报；
- 预期 candidate 只有状态、假设、标签和运行验证命题都匹配才正确，但不计 finding TP；
- 刻意含糊案例不得强制 pass/finding，任何一次都属于零容忍违规；
- 互补/无重要关系是问题 finding 的反例，错误问题 finding 计 FP；
- 重复报警不会增加 TP；首个正确组可以计分，多出的实质相同组计 FP/重复缺陷；
- G-018 类案例按维度评 assessment，并单独评无损分组。

资格集至少含 200 个独立评审语义交互，其中至少 50 个按冻结 CI 策略标注的阻断正例、
50 个最近邻反例、30 个刻意含糊/拒绝案例；每个将发布语义类别至少 20 个正例和 20 个
最近邻反例。一个案例可进入多个已声明分层，但 micro 总数只出现一次。

“阻断”只是冻结 CI 策略下的评测标注，不是新分类标签，也不从严重程度自动推导。报告
阻断 precision、总体 precision/recall、逐类与 macro、候选率、拒绝率和精确状态混淆。
AC-5 目标为阻断 precision ≥90%、总体 precision ≥85%、recall ≥75%。AC-6 要求语义
finding 组可行动性 ≥80%，刻意含糊强判为零。在有充分 holdout 运行前不宣称达到。

### 8.5 置信度、严重程度与可行动性

- 真值评审把严重程度看作影响，把置信度看作证据支持，二者不能互换；
- 对 high/medium/low 问题预测分别报告经验 precision 与 95% Wilson 区间；每档少于
  30 个时标“校准证据不足”，不外推；
- 声称置信度已校准前，样本充分的高置信档不得出现无法解释且实质低于低置信档的倒挂；
  PRD 没有数字校准误差目标，阶段 04 不自行发明；
- 可行动性由盲评按组做是/否判断：证据充分、下一步有边界且相关、用户无需相信黑箱分数
  就能行动；记录理由和分歧。

### 8.6 语义重复性与真实提供商资格

脚本提供商和已脱敏录制用于离线验证适配器契约，不能证明真实模型准确率。真实提供商
资格是独立的可选流程，只用合成数据和精确同意，并记录提供商、模型、适配器、提示契约、
策略和输入摘要。

要对某一真实 provider/model 作发布声明，需对冻结 holdout 独立运行三遍；逐遍和汇总
计分，三遍都达到点目标和零容忍条件。报告逐案例分歧/稳定性，不能用多数票隐藏波动。
提供商或模型变化使资格、同意和缓存键失效。

### 8.7 防泄漏与可复现

- 资格内容、标签和录制不得用于写规则、调提示、选例或在运行结束前调试；
- 开发与资格 ID/摘要分开；资格运行前缓存为空或按完整键精确失效；
- 每个分数绑定 fixture/输入版本、产品/结果/分类法/规则/规范化/profile/分组/语义契约
  版本、模式、策略、环境能力和无凭证模型元数据；
- 确定性资格每案例重复三遍，只删除已声明易变字段后比较规范结果。

## 9. 发布质量门禁

先判断证据是否有效。fixture 缺失、结果未封存、必需检查族 error、样本不足、真值非法
或评估工具损坏属于**执行/证据失败**，不得给出策略分数。有效结果低于测量目标或超过
finding 阈值属于**策略阈值失败**。二者都阻止发布，但必须分开报告。

“绝对”表示所有适用场景零容忍；“测量”表示必须按获批协议和最低样本量执行。

## 10. 追踪关系与有意缺口

[`traceability.csv`](../test-spec/traceability.csv) 共 155 条来源映射，覆盖：

- P0-R1 至 P0-R31；P1-R1 至 P1-R10；
- AC-1 至 AC-17；
- 全部实质类别、必需状态/限定符/对照类别及核心三轴、证据、裁决、分组契约；
- G-001 至 G-020；AD-01 至 AD-14；
- 阶段 03 全部 21 个组件边界与 18 个技术中立契约。

上述必需项不存在场景规范缺口。以下执行缺口是有意且可见的：

1. 不把运行证据生产者或因果验证作为已发布能力；只测试保留类型与运行验证边界；
2. 合成 profile 只测契约；版本相关规则发布前必须物化已评审的当前 Codex profile；
3. 未认证真实 provider/model，确定性发布也不依赖提供商；
4. 阶段 05 选定可回退操作并通过完整矩阵前，不声明任何修复受支持；
5. 本阶段不选运行器、物理结果存储、CLI 拼写、数字退出码、CI 平台或性能 SLO；
6. P2 的非 Codex 适配、运行轨迹、团队治理、托管界面和无人修复仍在 MVP 外。

## 11. 测试数据治理

### 11.1 来源与允许数据

- fixture 仅用合成数据，记录来源文档、作者/评审角色、日期、schema/fixture 版本、
  profile 与理由；
- 假秘密使用 `SYNTHETIC_SECRET_DO_NOT_SEND` 等唯一哨兵，不来自真实凭证，并在所有
  禁止输出端断言不存在；
- 禁止生产仓库、客户合同、个人路径/内容、遥测、真实凭证及未脱敏提供商流量；
- 已脱敏录制只有经评审确认无生产/个人数据和秘密后，才可用于适配器契约测试。

### 11.2 评审、版本、退役与本地化

- 状态为 `draft`、`reviewed`、`disputed` 或 `retired`；有争议 fixture 不计资格指标；
- G-001–G-020 ID 与规范预期稳定。改变决定性证据、三轴、不确定性或禁止结果，需要先
  修订规范英文文档，再发布新 fixture 版本并独立评审；不能为实现通过而削弱黄金；
- 不影响裁决的附加执行元数据也须物化评审并记录原因；
- 退役保留旧 fixture 与理由，ID 不重用，替代 fixture 链接旧案例；
- 英文 fixture 语义规范；本地化标题/理由只作投影。中文评审稿不会自动成为实际重复
  来源，除非本地化场景明确把它放入范围。

### 11.3 变更控制与防泄漏

黄金/资格变更 diff 必须评审决定性证据、语气/排除、区域、profile、三轴、禁止结果和
追踪。资格集与开发/提示/规则调优隔离。运行后改数据不能追溯“修正”分数，只能产生新
suite 版本和新运行。

## 12. 环境、隔离与执行 profile

1. 每个案例使用新的临时/虚拟根，并有运行前清单和清理后清单；开发仓库与用户配置永不
   成为目标；
2. 确定性 suite 禁网且无凭证，提供商模拟本地脚本化；
3. 真实提供商资格是独立 opt-in 环境，只用获批合成内容和精确披露授权；录制不是真值；
4. 环境 profile 声明大小写、Unicode/路径、符号链接、身份观察、权限、竞态安全替换、
   旧状态持久能力和不支持的修复操作；
5. 时钟、会话、过期、撤销和提供商时序均注入并记录，不依赖环境墙钟；
6. 并发变化发生在命名屏障，如全目标预检后或第二个应用/回退操作前；纯 timing race
   不能作为 oracle；
7. 输入枚举和规范输出顺序确定；随机性质测试记录 seed、生成值和最小反例；
8. 清理验证文件/元数据/链接/权限、提供商队列、缓存、恢复资料、打开句柄、进程和网络
   状态；清理失败属于执行失败并使分数无效。

## 13. 失败分诊与产物

每个失败或无效运行生成秘密安全的复现包，至少包含：

- 场景/suite 版本、seed/重复次数、失败断言、生命周期位置、预期/实际类型状态和禁止结果；
- 产品、结果 schema、分类法、规则、规范化、profile、分组、语义契约、适配器、
  provider/model 和 CI 策略版本；
- 冻结范围/同意/授权/方案摘要、脱敏输入版本清单、规范相对身份和文件系统能力；
- 盘点、覆盖、证据 ID/类型/血缘、案例/组 ID、运行结果、渲染/CI 与局部诊断；
- 模型调用状态、提供商/模型、请求/输入摘要、可安全请求 ID、响应校验、重试和同意清单，
  绝不含凭证或未批原文；
- 变更涉及的方案、授权决定、逐目标前后指纹、受保护旧状态引用、验证、变更/回退记录和
  故障时间线；
- 清理验证与环境/工具诊断。

产物使用工作区相对最小位置和明确 `redacted`/`withheld` 标记。秘密回显响应要隔离，
普通失败报告只记录安全事件和摘要。

修改代码或 fixture 前先分配一个主要类别：

| 类别 | 含义 |
| --- | --- |
| 产品缺陷 | 实现违反有效规范 oracle。 |
| Fixture 缺陷 | 物化没有表达获批决定性证据或事件。 |
| Oracle 缺陷 | 预期与规范冲突，或规范下仍含糊。 |
| Profile 缺陷 | 规则来源、兼容、大小写/路径或限制错误/陈旧。 |
| 环境/能力缺陷 | 声明的文件系统、时钟、网络、权限或提供商能力未真正提供。 |
| 运行器/评估器缺陷 | 隔离、故障注入、解析、计分、脱敏或清理工具错误。 |
| 提供商资格波动 | 真实模型变化但本地契约正确；不能重分类成确定性证明。 |

分类未解决时阻止对应资格单元。fixture/oracle 修正必须走变更控制，不能删除原运行。

## 14. 阶段 04 决定与被拒方案

| ID | 当前决定 | 被拒方案与理由 |
| --- | --- | --- |
| TD-01 | 使用带版本、技术中立的 JSON 场景 suite，显式记录所有边界和 oracle。 | 纯文字案例难以机器检查负向断言，容易漂移。 |
| TD-02 | 用问题/区域/维度作为诊断计分单元。 | 按文件/报警行会奖励重复，无法表示 G-018。 |
| TD-03 | 非诊断契约使用测试专用 `not_applicable`。 | 为修复/渲染虚构产品状态会污染三轴。 |
| TD-04 | 用合成虚拟文件、精确生成器和命名故障物化。 | 依赖用户配置不安全；现在写运行器会提前进入阶段 05。 |
| TD-05 | G-001–G-020 精确保留，但不视为统计充分。 | 重标黄金或用 20 例声称满足 AC-2/AC-5 会削弱规范。 |
| TD-06 | 分开开发、规范回归和资格 holdout。 | 一个可见语料会造成评测泄漏和过度调优。 |
| TD-07 | 预期 finding 被 candidate/拒绝时不给 TP，状态/覆盖另报。 | 部分分数可用来隐藏不作决定并抬高 recall。 |
| TD-08 | 绝对安全/隐私/不变量门禁与测量产品目标分开。 | 未授权写或泄密不能被准确率平均。 |
| TD-09 | 各渲染与一个封存图做语义对比。 | 独立文本快照可能掩盖状态、ID、覆盖差异。 |
| TD-10 | 重复性只排除已声明易变字段。 | 全字节比较会被合法时间影响；过宽规范化会掩盖漂移。 |
| TD-11 | 规定最低分层样本并报 Wilson 区间，不声称当前达标。 | 小样本或类别失衡百分比不是发布证据。 |
| TD-12 | 脚本/录制适配器测试与真实提供商资格分开，provider/model 变化使资格失效。 | 录制成功不能证明真实质量；强制在线会违反离线确定性。 |
| TD-13 | 后续每个受支持修复和能力 profile 都套完整安全矩阵。 | 一个正常文件编辑路径无法证明授权/并发/验证/回退。 |
| TD-14 | 需求、分类、黄金、决定、组件和契约使用机器可读追踪。 | 纯叙述追踪难以发现遗漏。 |
| TD-15 | 门控有界完成与清理，数字性能 SLO 推迟。 | PRD 没有有证据支持的性能目标。 |

## 15. 阶段 04 内部评审

2026-08-17 交付前完成以下文档级检查：

- **一致性：** 所有场景分开状态、标签、限定符；非诊断测试只用测试层哨兵；
- **追踪：** 所有要求的 P0/P1、AC-1–AC-17、阶段 02 类别/核心契约、G-001–G-020、
  AD-01–AD-14、架构组件和技术中立契约都有场景与门禁；
- **黄金保真：** 决定性证据、三轴、不确定性和禁止误分类均保留；静态证据从未改写为
  运行选择或因果；
- **隐私/信任：** 全部合成数据；范围/同意分开；秘密/脚本、提供商、输出、恢复和不可信
  内容都有负向断言；
- **失败模式：** 正/反/边界/拒绝/not-run/error、局部结果、渲染、CI、授权、应用、验证、
  回退、并发和清理失败均分开；
- **修复安全：** 精确预览/摘要、范围/会话/时间/撤销、全目标预检、前后状态、最多一次、
  失败即停、验证、安全回退和预检后竞态均覆盖；
- **范围：** 未引入产品代码、运行器、框架/provider/CI 选择、真实平台结论、打包或发布
  达标声明。
